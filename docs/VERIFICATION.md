## Original Chroma corpus and public source library

On 20 October 2026, the committed `chroma_store` was copied before verification. Chroma 1.3.5 reported one `economic_reports` collection with 4,767 stored vectors, each 384-dimensional, configured for cosine distance and Chroma's default embedding function. The seven PDF ID prefixes were `ecb` (467 chunks), `fm` (573), `frmp` (280), `gep` (1,524), `gfsr` (777), `oecd` (96), and `weo` (1,050). The source files in `data/reports_pdfs` were hashed with SHA-256 and matched to the public Source library entries. The index stores text and IDs but no page numbers or source URLs per chunk.

Every stored document was re-embedded with Chroma 1.3.5's `DefaultEmbeddingFunction`, which uses the local ONNX MiniLM model. **All 4,767 vectors passed** a maximum absolute coordinate tolerance of `1e-5`; the worst observed difference was `4.395843e-7`, and the lowest cosine similarity was `0.99999988`. A direct check of `ecb_chunk_0` showed the first eight stored and recomputed coordinates and the same match. This establishes numerical compatibility with that local model and those stored texts; it does not prove when or on which machine ingestion originally occurred. The reproducible command is `python scripts/verify_chroma_vectors.py --store <copy-of-chroma_store> --id ecb_chunk_0` or the same command with `--all`.

The public Source library links all seven report editions at their official publishers and displays local file hashes and index counts. The publisher links are external files; the local PDFs themselves are not served by the Worker, and a future publisher replacement could change the bytes behind a link. The public analyst still retrieves only the two curated ECB/OECD passages. The source library makes the historical corpus readable but does not enable Chroma on the public site.

The Source library release passed the existing 18 web tests and the TypeScript/Vite build. It was deployed to preview version `b8e02e8b-c803-42c3-979c-94395032e5b4` and production version `e2069b89-d01a-4779-a591-a315256ef698`. In-app browser checks on both hosts showed the seven report cards, counts, official PDF link targets, and the distinction between local corpus reports and the two curated public passages. The production page also loaded directly with `?view=sources` in a narrow viewport. Publisher PDF URLs were checked against official sites; the browser's new-tab PDF rendering was not independently confirmed for every link.
