# Engineering decisions

| Problem | Chosen approach and reason | Trade-off | Revisit when |
| --- | --- | --- | --- |
| Two codebases suggest two backends | Keep React and Cloudflare Worker as the single public product; label FastAPI/Chroma as a local prototype. This preserves the working URLs and same-origin API. | Python prototype is not visible to visitors. | A measured need requires capabilities the Worker cannot host, with a funded hosting and persistence plan. |
| Economic arithmetic must be explainable | Validate World Bank observations, then compute rates' changes in code as **percentage points**. Never ask a model to calculate or replace values. | Interpretation is deliberately narrow. | Indicators with different units or transformations need reviewed formulas and tests. |
| The official API can fail or revise data | Use bounded inputs, at most one retry for transient errors, request timeout, six-hour cache and explicit retrieval/provider dates. Surface an error and saved-demo option on failure. | Cache is local to a data centre and can be evicted; saved values are historical. | Traffic or reliability measurements justify a durable snapshot or provider redundancy. |
| The report corpus is tiny | Check two short, page-linked passages and metadata into a curated retrieval index. Match country, indicator and question terms. Label it curated retrieval. | Limited recall; this is not semantic/vector RAG or general report search. | A larger, licensed corpus and a documented retrieval evaluation justify embeddings and a versioned index. |
| The old Chroma artifact's vectors are unclear | Keep it out of the public application. `OpenAIEmbeddings` exists in Python source but is not passed to Chroma. | No public semantic RAG demonstration. | Rebuild with explicit document/query embedding configuration, checksums, provenance and compatibility tests. |
| Model credentials and spend | Public analysis remains deterministic; no Worker model secret, paid inference, public ingestion or implicit fallback disguised as AI. | No generative answer. | A suitable authorized service and budget exist; then add bounded server-side synthesis, rate limiting, grounded claim checks and evaluation before enabling it. |
| Export must represent what the visitor saw | Build the PDF in the browser from the displayed `Analysis` object. | Larger client bundle and portable font limits. | Large documents or accessibility requirements justify a server renderer. |
| Demo reliability | Ship a clearly dated saved snapshot alongside live mode. It can always demonstrate navigation, calculations, evidence and PDF without external access. | The snapshot has one observation per indicator, so no trend. | A newly reviewed, versioned snapshot is published. |
| Public operations | Separate preview and production Worker names; health does not depend on upstream; log request ID, route, status and error type on failures. | Local per-isolate request guard is not global rate limiting. | Meaningful public traffic requires an account-level Cloudflare rule and monitoring. |

These are implementation choices evidenced by the repository, not claims about the project owner's original intent. Cloudflare's [Cache API documentation](https://developers.cloudflare.com/workers/runtime-apis/cache/) explains the locality limitation. The [World Bank query documentation](https://datahelpdesk.worldbank.org/knowledgebase/articles/898581-api-basic-call-structures) defines `date`, `page`, `per_page` and `format`.
