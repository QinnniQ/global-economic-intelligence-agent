# Engineering decisions

| Problem | Chosen approach and reason | Trade-off | Revisit when |
| --- | --- | --- | --- |
| Two codebases suggest two backends | Keep React and Cloudflare Worker as the single public product; label FastAPI/Chroma as a local prototype. This preserves the working URLs and same-origin API. | Python prototype is not visible to visitors. | A measured need requires capabilities the Worker cannot host, with a funded hosting and persistence plan. |
| Economic arithmetic must be explainable | Validate World Bank observations, then compute rates' changes in code as **percentage points**. Never ask a model to calculate or replace values. | Interpretation is deliberately narrow. | Indicators with different units or transformations need reviewed formulas and tests. |
| The official API can fail or revise data | Use bounded inputs, at most one retry for transient errors, request timeout, six-hour cache and explicit retrieval/provider dates. Keep successful series when another live request fails; name missing indicators. Scheduled direct probes, a public monitor and a weekly saved-fixture comparison flag trouble. | Cache is local to a data centre and can be evicted; saved values are historical. Monitors sample a few series and locations. | Traffic or reliability measurements justify a durable snapshot or provider redundancy. |
| The report corpus is tiny | Check two short, page-linked passages and metadata into a curated retrieval index. Match country, indicator and question terms. Label it curated retrieval. | Limited recall; this is not semantic/vector RAG or general report search. | A larger, licensed corpus and a documented retrieval evaluation justify embeddings and a versioned index. |
| The old Chroma artifact's vectors need provenance | Keep it out of the public application. The local store and query path explicitly use Chroma's default ONNX MiniLM embedding function; all 9,317 vectors were numerically rechecked against it. | Numerical compatibility does not prove original ingestion history or retrieval quality. | Evaluate retrieval and claim support, then consider a hosted versioned index with access controls. |
| Model credentials and spend | Keep the observed-data path deterministic. Report mode retrieves short PDF passages and offers optional generation in the visitor's browser; the Worker has no model secret, paid inference, or public ingestion. | WebGPU and a large model download limit availability; a small model can misread evidence. | Measure retrieval and answer quality before considering a different model or hosted service. |
| Export must represent what the visitor saw | Build the PDF in the browser from the displayed `Analysis` object. | Larger client bundle and portable font limits. | Large documents or accessibility requirements justify a server renderer. |
| Demo reliability | Ship a clearly dated saved snapshot alongside live mode. It can always demonstrate navigation, calculations, evidence and PDF without external access. | The snapshot has one observation per indicator, so no trend. | A newly reviewed, versioned snapshot is published. |
| Public operations | Separate preview and production Worker names; health does not depend on upstream; log request ID, route, status and error type on failures. Add scheduled direct and external public probes with issue alerts. | Local per-isolate request guard is not global rate limiting; probes are sampled. | Meaningful public traffic requires an account-level Cloudflare rate rule and region-aware observability. |

The Source library and Report RAG share a page-level lexical index generated from all 13 verified PDFs. It publishes term counts, brief page leads and page references. Report RAG calls a bounded Worker route to select short excerpts from private hash-verified page assets. The observed-data analyst still has two curated passages. A 30-case search set checks source discoverability and unrelated-query abstention, not factual claim support.

These are implementation choices evidenced by the repository, not claims about the project owner's original intent. Cloudflare's [Cache API documentation](https://developers.cloudflare.com/workers/runtime-apis/cache/) explains the locality limitation. The [World Bank query documentation](https://datahelpdesk.worldbank.org/knowledgebase/articles/898581-api-basic-call-structures) defines `date`, `page`, `per_page` and `format`.
